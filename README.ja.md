# Proofdeck

*[English](README.md)*

別のアプリが書き換えるたびに自動で表示し直す、macOS 用の `.pptx` ビューアです。

Claude（に限らず何かの道具）に資料を作らせ、結果を見て、直してもらって、また
見る。この流れで PowerPoint を見張り役にすると、開いたときの版を出し続けるので
困ります。このビューアはファイルを見張り、保存から 1 秒ほどで描き直し、見ていた
スライドに留まります。

> 開発は Azure DevOps 上のプライベートリポジトリで行っていて、この GitHub
> リポジトリは公開用のミラーです（公開する価値があるときに更新します）。Issue は
> 見ています。Pull Request は手作業で上流へ取り込む形になるため、大きめの変更は
> 先に Issue で相談してもらえると助かります。

## できること

- 保存のたびに描き直します。上書き保存でも、一時ファイルからの置き換えでも拾います。
  書き込み途中のファイルは読みません。
- 見ていた場所を保ちます。描き直しても同じスライド番号、そのスライドが消えていたら
  最後のスライドへ。
- 左に番号つきのサムネイル（非表示スライドは薄く、番号に打ち消し線）、右に 1 枚表示、
  下に発表者ノート。
- 直前の更新で変わったスライドに印を付け、見ているスライドの前の版と今の版を ⌘B で
  切り替えられます。
- ノートの横のメモ欄に、スライドごとのフィードバックを書けます。⌥⌘C で「スライド 12
  「見出し」: …」の形にまとめてコピーでき、そのまま Claude に貼れます。
- 本文とノートの検索、4K の画像としてのコピー、PDF と PNG への書き出し、
  書き換えにも追従するスライドショー。
- ウインドウの位置と大きさ、見ていたスライドをファイルごとに覚え、終了時に開いていた
  ファイルを次の起動で開き直します。
- Claude 向けの MCP サーバー。いま見ているスライドを知る、このビューアの描画でスライドを
  画像にする、はみ出した文字を測る、メモを読んで済にする、ビューアを動かす、書き込み中は
  描き直しを止める、ができます。
- 描画は WKWebView の中の JavaScript で完結します。PowerPoint も外部の変換ソフトも
  要らず、通信も一切しません。

macOS 14 以降。Apple Silicon / Intel 両対応。

## できること・できないこと

| | |
| --- | --- |
| `.pptx` を忠実に表示 | おおむね。文字、図形、塗り、画像、表、非表示スライド、ノートが出ます。描画は [pptx-vanilla-viewer](https://github.com/ChristopherVR/ooxml) に手元の手直しを加えたもの（後述） |
| PowerPoint と画素単位で一致 | **しません。** 折り返しは CoreText のフォント計測どおりなので、PowerPoint で枠にぎりぎり収まるタイトルがこちらでは折り返す（またはその逆）ことがあります。アニメーションと画面切り替えは出ません |
| 編集 | **しません。** ビューアです。書いた道具で直して、更新されるのを見てください |
| Quick Look（Finder のスペースキー） | **同梱していますが、既定では使われません。** プレビュー拡張を入れて登録までしていますが、`.pptx` の既定のアプリが PowerPoint のあいだは、macOS は標準の Office 用プレビューを使い続けます。このアプリを既定にした場合は未確認です |
| オフライン | 動きます。スライドを描くページはアプリの中から専用の URL で配り、http/https は WebKit の段階で止めています |

## インストール

[Releases](../../releases) から zip をダウンロードして展開し、`Proofdeck.app` を
`~/Applications` に移動してください。自分でビルドすることもできます（後述）。

配布ビルドは ad-hoc 署名のみで公証（notarization）を受けていないため、初回起動は
macOS にブロックされます。**システム設定 → プライバシーとセキュリティ** を開き、
セキュリティの項目まで下がって、Proofdeck についてのメッセージの横にある
**このまま開く** を押してください。

資料は **ファイル → 開く…**、Finder の「このアプリケーションで開く」、または

```bash
open -a Proofdeck path/to/deck.pptx
```

| | |
| --- | --- |
| 開く / 最近使った項目 | ⌘O / ファイルメニュー |
| 再読み込み | ⌘R |
| 拡大 / 縮小 / ウインドウに合わせる | ⌘+ / ⌘- / ⌘0 |
| スライドの移動 | ← → PageUp PageDown Space、またはサムネイルをクリック |
| ノートとメモの表示切り替え | ⌥⌘N |
| 見ているスライドの前の版 | ⌘B |
| 検索 / 次 / 前 | ⌘F / ⌘G / ⇧⌘G |
| スライドを画像としてコピー | 一覧で ⌘C、どこでも ⇧⌘C |
| メモをまとめてコピー | ⌥⌘C |
| PDF / PNG に書き出す | ⌘E / ファイル → 書き出す |
| スライドショー | ⇧⌘↩、Esc で戻る |
| ヘルプ | ⌘? |

## Claude との連携（MCP）

アプリに MCP サーバーが入っています。Claude Code に一度登録すれば使えます。
アプリのメニュー **Proofdeck > Claude Code と連携する…** からでも、手でも登録できます。

```bash
claude mcp add proofdeck --scope user -- ~/Applications/Proofdeck.app/Contents/MacOS/proofdeck-mcp
```

| 道具 | すること |
| --- | --- |
| `list_open_decks` | 開いている資料の一覧。枚数、見ているスライド、直前の更新で変わったスライド、メモの数 |
| `open_deck` | `.pptx` をビューアで開く |
| `get_current_slide` | いま見ているスライドの番号・見出し・本文・ノート・メモ。「このスライド」が番号なしで通じる |
| `get_slides` | 範囲のスライドの番号・見出し・本文・ノート・非表示・変わったか・メモ |
| `render_slide` | ユーザーが見ているのと同じ描画で、スライドを画像にして返す |
| `check_layout` | 描いた結果を測って、枠からはみ出した文字、スライドの外の文字、重なった文字を返す（インチ） |
| `get_changes` | 直前の書き換えで変わったスライドと、増えた行・消えた行 |
| `get_memos` / `resolve_memo` | ユーザーのメモを読む、済にする（一覧が緑の印になる） |
| `goto_slide` | ビューアをそのスライドへ移す |
| `set_generating` | 書き込みの前に `on: true`、後に `on: false`。その間は帯を出して、終わりに一度だけ描き直す |

サーバーは、`~/Library/Application Support/Proofdeck/` にある、本人だけが開ける
Unix ソケットで起動中のアプリと話します。アプリが起動していなければ裏で起動します。
ネットワークでは何も待ち受けません。

ad-hoc 署名は**ビルドごとに署名が変わる**ため、配布版を更新するたびに macOS からは
別のアプリに見え、デスクトップなど守られたフォルダへのアクセスを聞き直されます。
Apple Development の証明書で署名した自前のビルド（後述）なら、許可は保たれます。

## ビルド

```bash
./build.sh install
```

描画ライブラリの npm 依存を入れ、手直しを当て、esbuild でページを 1 本にまとめ、
`project.yml` から XcodeGen で Xcode のプロジェクトを作り、アプリと Quick Look
拡張をビルドして `~/Applications` にコピーし、拡張を登録します。Xcode、Node.js、
`brew install xcodegen` が要ります。

署名にはキーチェーンにある Apple Development の証明書を使います（`DEVELOPMENT_TEAM=…`
で上書きできます）。証明書が無ければ ad-hoc 署名になります。`Proofdeck.xcodeproj` は
`project.yml` から作るものでコミットしません。ソースを足したら `scripts/bootstrap.sh`、
CI と同じ確認は `scripts/ci.sh` です。設計は [SPEC.md](SPEC.md) にまとめています。

アプリだけを手早く試すときは、今までどおり `swift build` でも動きます。

ビルドした `.app` はわざと `.build/` の中に置いています。プロジェクトのフォルダに
あると、Spotlight にインストール済みのものと二つ並ぶためです。

## 仕組み

| | |
| --- | --- |
| 監視 | 0.25 秒ごとの `stat` と、親フォルダの kqueue。上書きも置き換えも拾います。ZIP の終端レコードが揃ってから受け付けます |
| 描画 | pptx-vanilla-viewer（Apache-2.0。ooxml-core / ooxml-ui の上に作られている）を WKWebView で。ページは `ppv://` のスキームハンドラで配り、資料のバイト列も同じ道で渡します |
| サムネイル | 隠したもう一つの WKWebView に同じ資料を読ませ、1 枚ずつ撮ります。変わったスライドだけ撮り直し、仕事が無いときは捨てます |
| ノート | `notesSlide*.xml` を直接読むので、ノートだけの保存では描き直さずノートだけ更新します |
| 変わったスライド | スライドごとに、XML と関係ファイルの CRC で指紋を取って比べます。挿入や削除で番号がずれても、全部が「変わった」にはなりません。前の版は ⌘B のために手元に残します |
| 書き出し | 隠した表示を大きくして 1 枚ずつ撮ります。PDF は 2560 px の JPEG を、PNG は 3840 px で |

描画ライブラリへの手直しは `web/patches/patches.mjs` にあり、ビルドのたびに当て
直します。文字色の透明度、句読点のぶら下げ（ライブラリの幅ゼロの細工が WebKit で
読点を消していた）、pptxgenjs が書く重複した `a:pPr`、それに OOXML の定義とずれていた
五芒星のプリセットの四つ。上流へ還す予定です。

## なぜ作ったか

AI にスライドを書かせて直していくと、ビューアがそのままフィードバックの輪に
なります。PowerPoint は開いているファイルを読み直さず、Quick Look は図形の中の
文字を落とし、Office 系の変換ソフトは大きくてコピーレフトです。足りなかったのは、
この小さくて開いた部品でした。
